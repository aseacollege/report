# 한컴독스 UI 조사와 데스크톱 한글 단축키 기준

## 이번 조사 범위

한컴독스의 로그인된 한국어 HWP 편집 화면을 직접 관찰하고, REA로 별도의 공개 UI 정의와 공식 도움말을 수집했다. 학교 보고서 본문과 공유 링크, 세션 토큰은 이 폴더에 포함하지 않았다.

| 자료 | 범위 | 확인 수준 |
|---|---|---|
| [메뉴 조사](menus.md) · [JSON](live-menus.json) | 상위 메뉴 9개, 부모·하위 선택지 포함 151개 항목 | 상위 메뉴는 실제로 열었고 항목은 편집기 DOM에서 수집 |
| [UI 정의](ui-definitions.json) | HWP 2,909개 + 공통 1,915개 = 4,824개 노드 | REA 수집 및 XML 파서로 개수·구조 확인. 버튼 개수가 아니라 패널 등을 포함한 노드 수 |
| [대화상자 정의](dialogs.json) | 서로 다른 대화상자 ID 54개 및 참조된 명령·입력 요소 | 정적 정의의 합집합. 실제 사용 가능 여부와 다를 수 있음 |
| [실제 설정창 관찰](live-dialog-observations.json) | 글자 모양·문단 모양·표/셀 속성·편집 용지 | 열기·항목 확인·취소. 변경 적용은 하지 않음 |
| [데스크톱 한글 단축키](desktop-shortcuts.md) · [JSON](desktop-shortcuts.json) | 한글 2024 공식 일람 25개 표의 데이터 행 340개 | 개발의 우선 기준. 모든 실행은 미구현·미검증 |

| [근거 색인](evidence-index.json) | REA Evidence ID와 원본 식별값, 관찰 방법 | 후속 분석에서 재사용 |

## 개발할 때 지켜야 할 구분

1. 화면의 메뉴/버튼 목록과 명령 실행 기능을 분리한다. 버튼을 그렸다는 이유로 기능 지원을 표시하지 않는다.
2. 공통 XML과 HWP XML에는 뷰어·모바일·숨김·조건부 항목이 섞여 있다. 54개 대화상자를 그대로 모두 노출하지 않는다.
3. 표/셀 속성의 정적 정의는 6개 탭이지만 현재 화면에는 기본·여백/캡션·표·셀 4개 탭이 표시됐다. 실제 문맥을 우선한다.
4. 메뉴의 웹 표시 키와 실제 데스크톱 한글 키는 다르다. 사용자의 요청에 따라 `desktop-shortcuts.json`을 우선 기준으로 삼는다.
5. 원본 키 문자열과 문맥을 보존한다. 대체 키, 순차 키, 반복 키, 선택 상태, NumPad와 본 키보드 차이는 구현 단계에서 별도로 해석한다.
6. 편집 영역 이외의 검색창·팝업·과정운영 양식에서 문서 명령이 실행되지 않게 한다. IME 조합을 보호한다.
7. 원래의 한 글자 키가 일반 입력을 막지 않도록 본문·셀 커서·셀 블록·개체 선택 상태를 분리한다.

## 아직 확인하지 않은 범위

- 모든 하위 메뉴를 실제로 펼친 상태, 모든 개체/표/셀 선택 조건과 도구 모음의 활성 변화
- 팝업 전체의 실제 열기·모든 탭·선택지·숫자 제한 및 오류 메시지
- 수식·차트 데이터·AI 관련 네 대화상자의 내부 동적 콘텐츠. UI 정의에는 식별자만 있거나 입력 항목이 없음
- 340개 참조 행의 브라우저별 실제 입력 수신·명령 실행·IME 및 선택 결과
- 저장, 공동 편집, 한글 붙여넣기 및 문서 파일 호환

따라서 이 자료는 수집한 화면과 정적 리소스에 대한 메뉴 개발 기준이며, 제품 전체 기능 분석 또는 구현 완료 보고가 아니다. 기능 실행 시험은 원본이 아닌 빈 시험 문서에서 진행한다.

## 구현 전 검증표

각 단축키 항목마다 `지원 / 대체키 / 웹 제약 / 기능 미구현 / 미검증` 상태, 적용 문맥, 실행할 내부 명령 ID, 브라우저 시험 결과를 기록한다. 현재 `implementation=not-implemented`, `runtimeVerification=not-tested`를 유지한다. 실제 동작을 확인하기 전에는 지원으로 변경하지 않는다.
